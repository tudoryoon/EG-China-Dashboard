## Delivery

- Daily data refresh is scheduled through three Actions at **21:03, 21:10, 21:17 KST**, every day. All three call the same workflow and share a queued concurrency lock; read `main` after acquiring the lock.
- **Latest user correction (2026-09-28): publish usable updates even when 10 or more securities are missing. There is no failure-count or failure-percentage cap.** This supersedes the September 15 limit of 10. Retain failed securities' previous values and actual observation dates, and retry them in the next daily cycle. Count each failed security once across RS and Trend. When no usable old regional history exists, omit that security and disclose it in the failure report. Never invent fresh prices, dates or scores; new chart dates after a retained observation are null. Keep the unchanged calculation engines. Invalid constituents/schema, stale benchmarks and zero fresh securities for an entire regional market remain systemic publication failures.
- Accepted failures are recorded in regional `meta.missing`/`retained`/`omitted`, `data/taiwan-collection-status.json`, and the checkpoint's combined `collection` summary. Retained rows carry `dataStatus: stale` and the collection error; Taiwan also records `sourceCheckedAt`. Clear these fields after recovery. The shared policy is `failurePolicy: retain-and-publish` in `scripts/collection_policy.py`; never reintroduce a numeric cutoff without user instruction.
- Each Action retries collector-wide source failures up to six times with increasing waits. Never stage or publish invalid output. Tests/setup/audit/checkpoint errors do not dispatch recovery; post-collection validation exits 65 and stops automatic retry. Exhausted source/timeouts, push transport and delivery errors may dispatch one guarded 21:17 recovery under a shared lock, after checking the current commit and competing/newer runs. An accepted refresh with any number of disclosed security failures writes a checkpoint so later queued attempts skip collection and push until the next cycle. A GitHub Actions service/account outage can still prevent runners or dispatches from starting.
- Refresh Hong Kong/China screening and Taiwan revenue together, using `--strict --allow-partial` for Taiwan. Publish only after all validators accept the result with explicitly reported retained/omitted securities. A schema-4 checkpoint for the same 21:03 KST cycle must match every data and pipeline hash, including after rebasing before push. It suppresses later collection, commits and pushes even when GitHub delays runs past midnight. A morning manual refresh never suppresses the next 21:03 cycle.
- HSCI API rows must be filtered to explicit `isDummy=N` before validating the official constituent count; residual blank/dummy rows can remain after index reviews. Never bypass missing-member or duplicate-symbol checks.
- Source reliability repair (2026-09-09): Tencent is the primary source for all five ETFs and HSI/CSI800 histories, with Eastmoney ETF/CSI800 and Yahoo HSI fallbacks. Require the exchange calendar's latest completed session before accepting any provider, including HTTP-success responses. Retain entire adjusted histories from one provider; do not splice incompatible price adjustments or fill internal gaps. Tencent's shorter leading adjusted-history window may be trimmed explicitly. Log the selected provider/date and failed provider reasons. The manual `Verify Full Data Refresh` Action must perform real collection/validation with `--force`, has read-only permissions and never pushes/deploys. Scheduled jobs keep their normal checkpoint skip behavior.
- Scheduled publication validation inspects every regional row's `asOfDate` and last history observation. Explicitly reported failures may retain an older observation regardless of count. Undeclared stale rows, fabricated current observations and unreported omissions invalidate publication.
